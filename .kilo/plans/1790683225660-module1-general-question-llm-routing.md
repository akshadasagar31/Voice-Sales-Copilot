# Module 1 — General Questions Must Be Answered by the Active LLM

## Goal

When the final Module 1 transcript is a general question ("What is your name?", "Who are you?",
"What is your purpose?", "What can you do?", and any other ordinary question), the system must
route it to the **current active LLM** and speak the **actual generated answer**. It must never be
classified as a greeting or as lead data, and it must never substitute a canned/hardcoded response
for the LLM output. After speaking, the client must return to listening.

## Scope guard (do not regress)

Do not modify STT, VAD, TTS, Module 2, Telegram, RAG/Pinecone, UI chrome, or `backend/data/models_config.json`.
Do not touch `frontend/app/components/KnowledgeAssistant.tsx`.
Allowed edit surface only:

- `backend/services/lead_extractor.py` — `stream_general_query_tokens`, `answer_general_query` fallback only
- `backend/main.py` — `_stream_general_query_ws`, task lifecycle in `websocket_voice_stt` (module1 branch)
- `frontend/app/components/LiveCallVoiceCopilot.tsx` — `handleFinalSTTResponse` general-query branch only
- new test file `backend/tests/test_module1_general_question_llm_ws.py`

## Defects that override the LLM answer (fix these only)

### 1. Canned identity paragraph replaces the LLM answer — PRIMARY

`lead_extractor.py:2072-2079` (`stream_general_query_tokens`) and `lead_extractor.py:1936-1943`
(`answer_general_query`) both do `if not <llm output>: emit
"I am VoiceCopilot, your financial sales copilot. I have comprehensive knowledge of loan products..."`.

This fires whenever the active-LLM call yields nothing — blank/absent key, non-200, empty
`choices[0].message.content`, stream error, or task cancellation. The result is a spoken sentence
that *looks* like the answer to "What is your name?" / "Who are you?" / "What can you do?" but was
never generated by the LLM. This is the branch that overrides the general-question response.

Fix:
- In `stream_general_query_tokens`, when `has_streamed_any` is `False`, perform **one async
  non-streaming retry** against the same `endpoint_url`, same `target_model` (active LLM), same
  messages, using the existing `httpx.AsyncClient`.
- Only if that retry also yields nothing, emit a **neutral retry notice** (not an answer), and mark
  the turn. Suggested text, keyed by `lang_code`:
  - `en`: "I'm having trouble reaching my assistant right now. Please ask that again."
  - `hi`: "मैं अभी अपने असिस्टेंट से संपर्क नहीं कर पा रहा हूँ। कृपया दोबारा पूछिए।"
  - `mr`: "मी सध्या माझ्या असिस्टंटशी संपर्क साधू शकत नाही. कृपया पुन्हा विचारा."
- In `answer_general_query`, apply the same rule: replace the canned identity paragraph with the
  neutral notice so the non-streaming HTTP paths (`voice_entry`, `generate_module1_ws_response`,
  `/api/extract-lead` streaming) behave identically.
- Add a `llm_unavailable: bool` marker to the payload/frame so the client can tell "answered" from
  "not answered" and does not silently substitute anything.

### 2. General-query stream is cancelled mid-flight by socket teardown

`main.py:2126-2136`. When `emit_final_stt` runs inside `single_to_client` (`s_task`, the
`deepgram_is_final` / `deepgram_metadata` path), `client_to_single` completes first, then:

```python
for t in pending:
    if not t.done():
        t.cancel()          # cancels the in-flight general-query LLM stream
```

The client already received `type:"final"` with `has_subsequent_sentences: True` and
`immediate_sentence1: ""`, then the stream dies — zero or partial sentences, no `stream_complete`,
and the UI just re-arms listening. Symptom: nothing (or a fragment) is spoken.

Fix:
- Run the general-query stream as a detached `asyncio.Task` (`asyncio.create_task`) inside
  `emit_final_stt`, shielded from cancellation.
- Before cancelling pending tasks, `await` the stream task to completion with a hard deadline
  (e.g. `asyncio.wait_for(..., timeout=20)`), swallowing the timeout.
- Do not cancel the stream task while `stream_complete` has not been sent.

### 3. `_stream_general_query_ws` can finish without ever emitting a sentence

`main.py:1769-1817`. The `final` frame is sent with an empty `immediate_sentence1`, and the answer
arrives only as `sentence` frames. If nothing is buffered or the generator raises, the frontend's
early-return at `LiveCallVoiceCopilot.tsx:913-920` waits on `type="sentence"` frames that never
arrive; the TTS queue never completes; no audio plays.

Fix:
- Wrap the token loop in `try/finally`; in `finally`, flush any non-empty buffer as a `sentence`
  frame and always send `stream_complete`.
- Accumulate the full generated text. If the loop produced nothing, synthesize **one** `sentence`
  frame from the neutral retry notice (Defect 1) and still send `stream_complete`.
- Add `"is_general_query": True` and `"llm_unavailable": <bool>` to the `final` frame so the client
  can branch deterministically.

### 4. Frontend substitutes its own hardcoded answer

`LiveCallVoiceCopilot.tsx:859` and `:928` call `getAssistantAnswerFallback(rawTranscript, respLang)`
(`:562-581`), which hardcodes identity/capability/name answers. Combined with the early return at
`:913-920`, the client is the last place a canned answer can win.

Fix (minimal, inside `handleFinalSTTResponse` only):
- When `sttData.is_general_query === true` (new backend flag), never call
  `getAssistantAnswerFallback`; speak only what arrives on `type="sentence"` frames.
- When `sttData.llm_unavailable === true`, do not attempt any canned substitute; log and let
  `onQueueComplete` return to listening.
- Leave `getAssistantAnswerFallback` in place for the legacy `is_assistant_query`-only frames so
  Module 2 / older responses are unaffected.

### 5. "Return to listening" is already correct — verify, do not change

`onQueueComplete` (`LiveCallVoiceCopilot.tsx:794-818`) already clears buffers and calls
`startListeningTurn()`. The only thing that can skip it is `stream_complete` never arriving — which
Defects 2 and 3 fix. No change required beyond the regression test.

- `test_general_questions_are_not_loan_intent` — assert `is_loan_intent(...) is False` and
  `extract_name(...)` yields no explicit `my name is` / `this is` / `i am` match.

- `test_ws_streams_active_llm_answer_for_general_question` — drive the real

  is `type=="final"` with `is_greeting is False`, `is_assistant_query is True`,
  `is_general_query is True`; assert a `sentence` frame carries the mocked LLM answer verbatim; assert
  `stream_complete` arrives.
- `test_ws_answer_uses_active_llm_model_id` — assert the outbound payload `model` equals
  `get_model_manager().get_active_model("llm")["model_id"]`.
- `test_llm_failure_emits_retry_notice_not_canned_answer` — make the LLM raise and then return empty;
  assert no emitted `sentence` text equals / contains the old hardcoded identity paragraph

- `test_hindi_and_marathi_general_questions` — same routing assertions for

## Risks

- Changing the fallback text in `answer_general_query` may affect existing tests that assert the old
  identity paragraph. Grep for "comprehensive knowledge of loan products" across
  `backend/tests` before editing and update only fallback-specific assertions.
- `asyncio.wait_for` on the detached stream task must not block the Deepgram pool release in the
  `finally` at `main.py:2141-2151`; keep the deadline short (20s) and always release.
- `is_general_query` is a new field on the `final` frame. It is additive; the frontend change is
  gated on the field being `true`, so older backend responses keep the current behavior.
